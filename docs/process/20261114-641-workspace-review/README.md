# Workspace recovery maintainer review

The source candidate for [#641](https://github.com/juangcarmona/lighthouse/issues/641) is retained in [PR #668](https://github.com/juangcarmona/lighthouse/pull/668). Its [original native attempt](https://github.com/juangcarmona/lighthouse/actions/runs/43633353118) passed host verification but reported a blocked assessment because Ponytail was unavailable in that worker. The maintainer performed the required code and architecture review with the installed skill and corrected two findings: local recovery storage now has a filesystem-entry limit, and adapter test observations now measure the filesystem instead of recording fixed zeros. The original blocked outcome is preserved.

The [review receipt](review-receipt.json) binds the reviewed code and tests by SHA-256. The implementation extends the existing ownership journal and stopped-process checks, retains candidate changes and diagnostics before disposal, and verifies workspace absence. It preserves substituted paths, active or unknown owners, original source, named volumes and caller-owned caches. Local recovery storage stops admission at 32 bundles, 512 MiB of content or 8,192 filesystem entries; it never evicts modified source to admit another attempt.

Focused checks passed 36 tests with two optional real-Docker skips. The [adapter observations](adapter-observations.json) cover three failed complete adapter invocations using a Docker shim, including generated dependencies and caches; a nonzero measurement control checks the filesystem counter. The [workspace observations](workspace-observations.json) cover five real SIGKILL/recovery process repetitions. Disposable state returned to three entries and 12,288 allocated bytes after each recovery while the foreign sentinel and retained candidate/evidence survived. These filesystem recovery fixtures do not execute complete native workers.

Repository verification passed 1,290 tests with 14 optional skips and validated all 136 public-site files. Strict OpenSpec validation passed, and citation verification reported zero errors with the same 309 baseline warnings, including 295 stale citations. The original installed-harness attempt left all 22 owned containers absent; its dedicated provider paths grew by 24,576 allocated bytes and six inodes, with no measured npm-cache growth. That observation concerns the old installed harness, not qualification of this candidate.

Package release, selected workflow/harness adoption and installed acceptance remain separate. Keep #641 open until a controlled series of complete native executions covers success, failure, timeout, cancellation and abrupt-loss recovery, with byte/inode/resource inventories and retention rollover. Delivery outputs and legacy ownership records still require their documented operator/provider reconciliation; neither remote artifact expiry nor these source tests establishes their disposal. Preserve active workers and historical unowned resources throughout qualification.
