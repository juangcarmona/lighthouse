# Native scoped memory qualification

Two actual OpenCode model workers used installed public SDLC **0.30.0**, from release `1f40faf4ce78945325ce534eb1de49d1e8f42e38`, against the same immutable engineering fixture. The host used the existing memory API and private SQLite provider. [The retained projection](native-memory.json) records native-event/context hashes, installed module hashes and the private operator receipt's hash; project identities and full source references remain outside this repository.

The first worker completed with optional memory disabled, inspected current source and ran its dependency-free test command: 34 passed, zero failed. The host independently ran the same command, reviewed that exact non-sensitive finding and retained it under a separate write grant. The second worker received one bounded, untrusted recalled record through its read grant, checked it against current source and ran the same 34 tests. Its report identifies the first run and the exact recalled source reference. SQLite was reopened between operations and never mounted into either worker.

Host-side checks returned no records for a different project/repository. An explicit management grant then marked the finding stale; subsequent recall returned no records. Both named worker containers are absent and source file hashes are unchanged. Eligibility used an exact full-record allowlist for this exercise; it is not a general privacy classifier.

This completes the remaining installed-worker memory exercise in [#270](https://github.com/juangcarmona/lighthouse/issues/270), alongside its already delivered CodeGraph and compact-output children. It demonstrates operator-provisioned integration through the existing library. It does not activate automatic memory injection in GitHub workflows, deploy a shared service or qualify a representative product-delivery pilot. The separate [#99 pilot](https://github.com/juangcarmona/lighthouse/issues/99) still needs real delivery observations and a supervised comparison.

The first driver's overly narrow path/tool/reporter assertions were corrected after inspecting the retained native events; the completed first worker was reused. No model execution was repeated to repair those assertions. Ponytail guided the reuse of the existing integration surface. This human explanation received the packaged Plain English and Humanizer fallback reviews and a comparison against the retained results.
