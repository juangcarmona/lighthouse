## Goal

Publish a readable overview of Lighthouse that explains its authorities, lifecycle, routes, labels and adoption evidence with generated diagrams.

## Trigger

The maintainer runs the public-site build or a release pipeline prepares a preview or production publication.

## Preconditions

ProductShape and ArcShape sources validate, the workflow projection identifies its source artifacts and the site build has access to the generated package CSS and brand assets.

## Main Flow

1. The build loads the ProductShape product boundary and lifecycle projections.
2. The build loads the selected ArcShape architecture sections and Mermaid diagrams.
3. The build renders the public overview, adoption routes and sequence diagrams into the static site.
4. The verifier checks source references, generated assets, links, diagrams and package CSS.
5. GitHub Pages receives only the verified static output after the workflow validates the ProductShape and ArcShape inputs.

## Alternative Flows

A local preview can build the same output without publishing it. An architecture-only reader can be generated by ArcShape when the public overview is not part of the change.

## Failure Conditions

Product or architecture validation fails, a source reference is missing, a Mermaid diagram cannot render, generated assets drift or deployment configuration points at another output.

## Postconditions

The public site is a verified projection with traceable source authorities, or publication stops with an actionable report.
