# Lighthouse 0.3.0 upgrade guide

## Prerequisites

- The repository has a valid `lighthouse.json`.
- The working tree is clean or the update is isolated in a reviewable branch.
- `.lighthouse/upgrade.json` exists and records the managed projection hashes.
- Node.js 22 or newer is available.

If `.lighthouse/upgrade.json` is missing, run `lighthouse reconcile --dry-run`, review the plan and then run `lighthouse reconcile --apply` to establish ownership evidence. Resolve any reported conflicts first.

## Plan the update

Run `lighthouse upgrade` to preview all Lighthouse-owned scopes. Use `lighthouse upgrade --scope harness` for `LIGHTHOUSE.md`, hooks, the guard script and the repository workflow, or use `lighthouse upgrade --scope sdlc` for the SDLC control-plane projection.

The plan reports the installed package and baseline, the selected scopes, prerequisites, file classifications, preserved content, verification command and recovery action. `lighthouse upgrade --format json` produces the same plan for a review tool or CI job.

## Apply the update

Review the plan and run `lighthouse upgrade --apply` with the same scope. Lighthouse writes only missing or provably managed projections, records the new ownership hashes and preserves customized files for review.

Run `lighthouse verify` after the update. A preserved customized projection may still report drift; resolve it through the normal repository change route before making the verification gate required.

## Recovery

If the update stops, keep the plan output and resolve the stated ownership or prerequisite issue. If a write fails, Lighthouse restores the files changed by that attempt; restore the branch or rerun the plan after correcting the reported condition.
