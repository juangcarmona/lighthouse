# Optional compact command output

Operators can set `"compactOutput": true` in their private engine configuration after installing and pinning RTK in the selected worker image. Lighthouse qualifies [RTK 1.2.0](https://github.com/rtk-ai/rtk/releases/tag/v1.2.0), source `e288a18c04452fd26192f59132e5324a8bb6924d`. Installation and upgrades leave this option disabled. Turning it off restores ordinary output; existing logs remain evidence.

The worker's managed command slot executes the original command once and saves its complete stdout/stderr. For successful `git status`, `git diff`, `git log`, `rg`, `grep`, `find`, `fd`, `tsc`, `pytest` and `vitest` commands, the adapter can feed that retained log to `rtk pipe --filter`. It uses no OpenCode hook and rewrites no executable command. Unsupported commands and failed commands remain unabridged. Missing RTK, incompatible filters, errors, warnings, timeout, oversized input/output or an empty/non-reducing result produce a visible fallback to the complete log. Shell-wrapped commands remain unabridged because their command identity is not inferred.

The terminal command receipt records the presentation status and `rawLog`; compact output also prints the full-log path. Read that file for complete diagnostics. For a failing build or test, inspect both the original `exitCode` and full output before continuing. Caller redirection into the same managed log keeps the original output; use a separate caller log when compact presentation is wanted.

Only the model's command presentation changes. Trusted host commands, check receipts, CI, content digests and publication decisions retain their existing inputs. The option is passed only to the worker container. It grants no new tool, write, review or merge authority. The engine image, operator configuration and retained log lifecycle remain operator-owned.

Task-specific lifecycle instructions already load from the selected packaged skill; required repository policy and startup/fallback instructions remain in force. The adapter adds no always-loaded RTK plugin or replacement system prompt. A real-worker exercise must establish compact output and diagnostic recovery independently of source tests; this feature claims no token or cost savings.
