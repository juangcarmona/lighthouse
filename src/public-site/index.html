02 / AGENTIC DEVELOPMENT ENVIRONMENT

Work with an agent in your repository.

Instructions, skills and verification travel with the code. The developer still owns the request, scope and decision.

01

Give it context

The agent reads the repository entrypoint and the guidance for the selected package or stack.

02

Keep the work bounded

Skills and commands describe the task, the files it owns and the evidence it should return.

03

Check the result

Run the relevant verifier and review the change before accepting it.

IN PRACTICE

Ask for a .NET use case. The agent follows the repository and profile contracts, edits the selected slice, then reports the result of npm run verify:dotnet. The check provides feedback; it does not approve the change.

03 / DELIVERY WORKFLOWS

From issue to reviewed change.

With the selected workers installed, an owner requests a stage through GitHub. Each result links to the work and the next decision.

01

Triage

Assess the request and estimate it. Stop for the owner's decision.

02

Refine

Define acceptance criteria or ask a specific question.

03

Implement

Plan, change code and verify. Publish both plan and code in a draft PR.

04

PR & checks

Apply feedback in the same PR. Wait for required checks and owner approval.

05

Integrate

Assess the current approved head and merge only when authorized.

06

Review

After post-merge CI, record the retrospective and close the issue if passed.

HUMAN STOPS

Questions, future, human reservations and failed checks pause continuation. A passing worker run alone does not authorize merge.
