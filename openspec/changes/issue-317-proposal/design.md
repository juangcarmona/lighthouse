# Design

The catalogue defines five native command names; an executable matrix checks each against routeIssue and the installed router admission expression. State, classification and overlay labels retain their roles. Supported command events reach the router even when denied, so they can receive an explicit outcome rather than an all-skipped run.
<!-- pdac:cite id="BR-LABEL-ROLES" digest="sha256:1c708a16c7730f0fe94cef9efa5f729e3d64a6b4943dcc06adf6759ce062725c" -->

Integration resolves a single open repository-owned implementation PR for the issue and default branch. It requires a non-draft complete head, current owner approval and passing effective required checks. The router passes its captured binding to the dispatch job; the worker reauthenticates the original event and binding. Publication rechecks implementation identity, receipt, approval and the existing completion snapshot. The authorization always has merge false. The request label is consumed after a published result; reservations retain their separate cancellation semantics.

A denied request publishes its missing prerequisite with the next action. Existing dispatch and handoff receipts handle repeated events; this change adds no scheduler or retry authority. Adoption creates missing labels and retains customizations. A real worker failure uses the existing verified reconciliation record before applying execution-failed.
