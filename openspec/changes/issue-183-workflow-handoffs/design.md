# Design

The GitHub adapter observes execution, authenticates the dispatch and owns tracker mutations. A shared handoff contract renders the same visible structure for requests, validated outcomes and trusted host failures; it does not grant stage, retry, merge or product authority. A current attempt is established from trusted dispatch identity, run and attempt evidence before any label or comment is changed. Unknown or stale evidence stops mutation and is reported for reconciliation.

The label capability declares `execution-failed`; installation and reconciliation preserve existing adopter labels and explicitly report a missing projection. Status labels are changed before the explanatory comment; independent reservation overlays remain intact. The publisher records stable attempt-specific markers so replay checks existing effects and repairs an interrupted transition without creating duplicates. Existing recovery observes those facts and retains its current retry limits and authorization.

A question is a distinct pending item with its full text and reply location. Validated answers remain tied to that item through continuation and do not authorize review or merge. A review state requires a confirmed accessible result. Host failures and cancellation are reported from trusted job observations without creating a synthetic agent envelope. Unknown observations stay unknown.

The change updates source workflows and regenerates locks with the pinned compiler. Tests cover successful review, questions and continuation, failure and cancellation, missing labels, duplicate and stale attempts, and interrupted publication. A controlled GitHub issue or PR verifies the rendered sequence without depending on the original engine defect.
