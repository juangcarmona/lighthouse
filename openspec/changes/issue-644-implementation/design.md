# Design

The CLI uses the pinned ProductShape core API to inspect explicit configuration and the provider CLI to validate the v1alpha2 model. A required `foundation.pdac` check runs even without recorded authorities or the public site. Existing recorded-authority checks retain their scope. Initialization and projection repair can proceed with an explicit pending product adoption; they never claim compliant adoption or mutate provider content.

The mechanical model migration moves the 44 existing BR-to-UC selectors into UC governance and preserves journey/context scope, IDs, body text and approval status. The isolated migration validates the resulting 142-artifact model and every active overlay, restoring original bytes on failure. Current architecture citations are reviewed and refreshed through ProductShape; historical run outcomes and digests are preserved.

The evidence builder retains its count-independent byte bounds and immutable baseline check. Its index adds serialization metadata independently of the pinned core version. LC/SB reports include provider-parsed frontmatter and body. Delivery skills point to one packaged verification guide; ProductShape's external evidence verifier owns target/schema/citation checks.

Tests exercise actual CLI commands and a representative publication domain. The domain tests cover valid transitions, forbidden operations, terminal states and invariants, retain actual passing/failing runs, and observe stale model citations without rewriting their original outcome. Clean-consumer verification repeats these checks against packed CLI and SDLC files. npm publication, adopter deployment and overall issue #641 qualification remain separate effects.
